# PIBO Studio 제품 사이트·블로그 통합 · 2026-10-15

요청한 두 게임의 사이트와 블로그를 `/Users/danpro/Documents/GitHub/pibostudio`의 기존 Astro 구조 안에 구현했다. 홈페이지의 원래 디자인·마스코트·애니메이션을 유지하면서 실제 제품 카드와 글 목록을 연결했다. 개발 중인 저승분식과 공개된 StockPets의 상태는 구분한다.

## 구현된 범위

| 화면 | 저승분식 | StockPets |
|---|---|---|
| 제품 소개 | 실제 픽셀 음식 7종 미리보기, 실제 게임 화면, 특징·FAQ | 픽셀 펫 8종 미리보기, 실제 게임 화면, 스토어 링크·FAQ |
| 블로그 | 한국어·영어 소개 글 3편씩 | 기존 한국어·영어 글 5편씩을 PIBO 형식으로 이관 |
| 가이드 | 첫 한 끼, 중단·복귀·저장 | 기존 10편씩 이관 |
| 지원·정책 | 게임 지원·개인정보 안내 | PIBO 문의, 기존 공식 개인정보 페이지 연결 |

제품 경로는 `/{product}/`, `/{product}/blog/`, `/{product}/guides/`, `/{product}/support/`. 한국어는 `/ko`가 앞에 붙는다. 홈페이지·전체 제품·게임·앱·전체 저널은 데이터에서 생성된다. 실제 앱 항목이 없어 앱 목록에는 정직한 빈 상태를 둔다. 저승분식은 공개 다운로드를 아직 제공하지 않는다.

StockPets 독립 사이트는 유지한다. 이관한 글은 원문 링크를 남겼다. 상대 `/get/` 링크는 확인된 공개 스토어 주소로 교체했고, 오래된 광고·구매 없음 문구를 현재 iPhone판 안내로 고쳤다. iPhone판 언어는 17개로 반영했으며 Android의 조건은 해당 스토어 안내를 확인하도록 표기했다. Pibo의 조용한 농장 가이드 주소에서도 오래된 no-ads 표현을 제거했다.

## 실제 검수

- 정적 빌드 성공. 전체 생성 HTML의 내부 링크·이미지·ID·앵커, canonical, 상호 번역 연결, JSON-LD, RSS·sitemap 일치 확인. `_example`은 공개되지 않는다.
- 브라우저에서 한국어 홈페이지 → 제품 → 블로그 → 글 이동, 영어 전환, 음식·펫 선택, 테마 선택·유지, 모바일 메뉴·Escape 닫기를 사용했다.
- 320px에서 한국어 홈·제품 목록·저널·두 제품·글·표 포함 가이드·지원·개인정보, 영어 StockPets 글을 열었다. 페이지의 가로 넘침과 로딩 완료 후 깨진 이미지는 발견하지 않았다. 390×844과 기본 데스크톱 화면에서 실제 스크린샷을 남겼다.
- 서로 다른 slug를 쓰는 StockPets 닷컴 버블 글의 언어 전환도 같은 글의 영어 주소로 이어졌다.
- 움직임 줄이기의 기존 matchMedia 분기와 신규 CSS 전환 제거 경로를 점검했다. 브라우저 도구가 해당 OS 설정의 에뮬레이션을 제공하지 않아 **실제 설정에서 시각 확인한 것으로 표현하지 않는다**.
- 게임과 StockPets 독립 사이트의 이 작업 시작 시 보존한 원본 파일 해시가 그대로임을 확인했다. PIBO의 기존 파일도 적용 전에 보존본과 대조했다.

이번 검수는 에이전트의 로컬 브라우저 확인이다. 실기기 Safari·VoiceOver와 독립적인 사람 사용성 관찰은 별도로 하지 않았다. 글과 에셋 수를 상품 품질의 근거로 쓰지 않는다.

## 보존·확장

원래 PIBO README는 `README-before-product-integration.md`에 보존했다. 자산 출처·복사 해시는 ASSETS.md와 asset-provenance.json에 기록했다. 새 제품은 데이터와 이미지 폴더를 추가해 같은 화면을 사용한다. ADD-GAME/ADD-APP/ADD-POST 문서에 절차를 적었다. 실제 게임 파일·저장·서명·App Store Connect는 이 작업에서 수정하지 않았다.

## 공개 전 남은 조건

1. 사용자가 화면과 정책 문구를 확인하고 공개 배포를 지시해야 한다. 이 로컬 구현 요청으로 Git push·배포를 수행하지 않았다.
2. pibostudio.com은 이번 브라우저 조회에서 DNS 연결 실패를 보였다. 호스팅·도메인 연결 후 HTTPS와 실제 모든 제품·블로그 경로를 확인해야 한다.
3. 공개 배포 단계에서만 현재 noindex/nofollow와 robots 차단을 제거하고 실제 공개 URL의 메타데이터·사이트맵·피드를 재확인한다.
4. 지원 메일 수신·회신을 실제로 확인해야 한다. 기존 라우팅 문서나 mailto 링크만으로 수신 가능하다고 판정하지 않는다.
5. OS 움직임 줄이기, 실기기 Safari·VoiceOver를 확인하면 관련 미검증 표기를 해소할 수 있다.

스튜디오 별도 about/contact/404는 이번 두 제품 통합 범위 밖이다. 기존 홈페이지의 스튜디오·문의 구역과 공통 지원 화면은 사용할 수 있다. 전체 홈페이지를 공개하려는 후속 작업에서 별도 화면을 완성할 수 있다.
